00 / BRIEF

产品简报

一句话定位、解决的真问题、目标用户与价值链。

愿景

从离散任务的月度催办，转为以项目为中心的执行与问责。项目是价值单元，任务是落地方式，人是责任主体。

用户

Boss(决策) · PMO(运营) · Leader/PIC(执行管理) · 员工(执行)。
早期采用者 = Boss + PMO。

北极星

子项目里程碑按时达成率。一切功能服务于"让更多子项目按预期时间完成"。

今天的真问题

01 看不到项目全貌
任务离散、按象限+月份催办，脱离"为了哪个项目目标"。
02 项目结构扁平
项目只是标签，无法表达 项目→子项目→任务 的层级。
03 时间线只到任务级
没有项目/子项目级的滚动时间线与健康度。
04 问责激励无客观依据
事故、KPI、晋升各自为政，与项目执行结果脱钩。

01 / LEAN CANVAS

精益画布

内部工具版（收入流 → 组织价值/ROI）。

问题

项目无全貌 / 任务脱离目标 / 时间线只到任务级 / 问责激励无依据。替代品：飞书任务 + 多维表格手工拼。

客户细分

Boss · PMO · Leader/PIC · 员工。早期采用者 = Boss + PMO。

独特价值

项目穿透 + 时间线问责——一屏看清所有项目健康度并追到人。

解决方案

三级结构 + 分层甘特 + PIC + 事故联动 + KPI 决策支持。

渠道

飞书内嵌 + 卡片提醒 + 月报。

组织价值 / ROI

决策提速 · 交付准点率↑ · 问责透明 · 激励公平 = 减少延期损失 + 节省对账时间。

成本

研发迭代 · 项目结构录入维护 · 组织流程变更阻力(最大隐性成本)。

关键指标

里程碑准点率 · 项目归属率 · 未归属积压 · 驾驶舱使用率 · 事故闭环率。

门槛优势

已沉淀真实组织数据 + 飞书深度集成 + 已有任务/事故/打分基建（非从零）。

02 / ROADMAP

规划蓝图

一步步来：先把项目的"架子"搭好 → 让人一眼看清项目 → 出了问题能追责 → 最后才谈打分晋升。顺序故意这么排——没有可信的项目数据，谈绩效就是空中楼阁。

V0
打地基

先把"项目"立起来，任务必须归到项目下 ● 已上线

解决"任务一大堆、却不知道是为了哪个项目"的问题。
  • 项目下面能再分子项目（比如"印尼电商"项目下分"支付通道接入""运营团队搭建"），最多分两层，够清晰又不乱。
  • 新建任务时不选项目，就进"未归属"待整理区——不再像以前那样被偷偷塞进默认项目。等于提醒你"这条还没归位"。
  • 随时能把未归属的任务挂到某个项目或子项目下。
V1
项目驾驶舱

打开驾驶舱，第一眼看到的就是"有哪些项目、状态怎么样" ● 已上线

从"看一堆零散任务"变成"看项目全局"。
  • 新增「项目」页签，老板 / PMO / 管理员一进驾驶舱默认就看它。
  • 每个项目一张卡片：完成进度（百分比）、健康灯（绿=正常 / 橙=预警 / 红=逾期）、负责人、任务数（多少做完、多少逾期）、起止时间。
  • 健康灯怎么亮（大白话）：有任务过了截止还没做完 → 红；进度明显落后于时间，或快到期了进度还很低 → 橙；其余 → 绿。
  • 层层钻进去：点项目看它的子项目，点子项目看具体任务。
  • 时间线视图（甘特图）：项目一条横条、子项目一条、任务一条，全排在同一根时间轴上，颜色就是健康状态——谁拖期、什么时候干，一目了然。
  • 项目负责人（PIC）：给项目指定一个真实的人，还能按负责人筛选——"只看张三负责的项目"。
V2
出了问题能追责

事故能直接挂到"哪个项目、哪个任务、谁的责任" 规划中

让"追责"有据可依，而不是事后扯皮。
  • 登记事故时，关联到具体的项目 / 子项目 / 任务。
  • 在项目视图里直接看到这个项目出过哪些事故。
  • 任务逾期或反复延期时，系统主动提示"要不要登记一个事故"。
V3
打分晋升的参考（人来定）

打 KPI、评晋升时，把客观数据摆出来供参考 规划中

系统只负责"把事实摆清楚"，绝不替你打分。
  • 每个人一个面板：他在各项目里完成了多少任务、关联了多少事故，作为打分时的参考依据。
  • 季度绩效报告：按项目维度看每个人的贡献。
  • 晋升参考视图：只是把多维度数据摆出来，最终永远由人拍板。
为什么放最后：人事决策风险最高，必须建立在前面三步攒下的可信数据上，且永远人工复核——系统不自动定分、不自动晋升。

04 / MATURITY GAP

一个成熟产品还缺什么

当前是"项目驱动 MVP"——闭环已通，但离成熟产品仍有距离。按主题盘点，标注优先级（基于现有代码与组织风险评估）。

主题现状 / 缺口优先级
协作任务无评论 / @提及 / 附件 / 关注者 / 活动流。成熟产品的协作发生在任务里；现在只能改字段。高
通知中心只有飞书卡片 + cron 提醒。缺站内通知中心、已读/未读、@提醒、升级链、摘要。偏好表已部分存在。高
搜索无全局搜索（跨任务/项目/事故/人）。规模一大就找不到东西。高
可扩展性项目组合 API 每次全表扫描所有任务；outbound 同步每分钟全表 diff。任务量到 1 万+ 会慢——需缓存/分页/增量。高
移动端拖拽排序不支持触屏；无移动专用布局 / 飞书小程序原生体验。领导常在手机上看。中
审计与合规有 trace_id / sync_log，但缺字段级变更审计（谁在何时改了什么）、审批流、不可篡改日志。问责系统尤其需要。高
计划能力无任务依赖 / 关键路径 / 资源负载 / 容量规划。甘特目前是展示型，非排程型。中
自动化 / 模板无规则引擎、项目/任务模板、周期任务、SLA。重复性工作仍手工。中
报表 / 导出缺自定义报表、Excel/PDF 导出、定时报告、趋势分析。多维表格目前承担部分导出。中
可观测性 / 运维worker 已 systemd；但缺错误追踪(Sentry)、监控告警、健康看板、备份/容灾演练。API/web 仍 nohup。高
质量保障单测充分(203)，但缺E2E 覆盖、负载测试、无障碍(a11y)、i18n（目前仅中文）。中
数据治理缺数据留存/归档策略、对账自动化、未归属积压治理。同步对账目前半自动。中
权限粒度角色级门禁已有；缺字段级/行级精细权限、SSO 之外的身份源、密钥轮换流程。低
集成飞书深度集成 + 多维表格；缺日历双向、对外 Webhook/API、第三方导入。低
用户引导缺新手引导、空状态指引、帮助文档、更新日志。组织推行新流程时摩擦大。中
绩效成熟度V3 将做打分输入；成熟形态还需 OKR 对齐、权重/校准、360 反馈、晋升工作流（且始终人审）。低

建议优先级：先补协作（评论/附件）、全局搜索、可扩展性、审计、可观测性——这五项是"内部催办工具"迈向"可信赖的组织级系统"的门槛；其余按使用反馈推进。绩效自动化永远保持人审。

# 多维表格结构设计

## 1. 目标

定义多维表格中的表、字段、视图和使用边界。多维表格在本系统中承担“业务操作台 + 运营台账”的角色，不是最终唯一主档。

## 2. 表结构建议

### 2.1 `task_master`
映射中心主任务表。

建议字段：
- 任务唯一ID
- 任务标题
- 任务详情
- 任务类型
- 任务负责人
- 直属上级
- 部门
- 归属 leader
- 发起人
- 指派人
- 指派关系类型
- 状态
- 进度百分比
- 最新进展
- 开始日期
- 预计完成时间（due_at）
- 实际完成时间（completed_at）
- 阻塞原因
- 延期原因
- 剩余天数
- 是否延期
- 当前归属月份
- 来源月份
- 是否继承
- 继承来源任务ID
- 老板关注
- 飞书任务ID
- 日历事件ID
- 最近同步状态

### 2.2 `task_progress_log`
映射任务进展日志。

### 2.3 `monthly_snapshot`
映射月结快照。

### 2.4 `sync_exception`
可选，用于运营人员在表内查看同步异常。

## 3. 视图建议

### 员工视图
- 我的任务
- 我的本周应完成
- 我的临期任务
- 我的已延期

### Leader 视图
- 团队本月任务
- 团队本周应完成
- 团队风险任务

### 老板视图
- 本月重点任务
- 按 leader 汇总
- 本月继承任务
- 已延期任务

### PMO 视图
- 同步异常
- 月结核对
- 缺失负责人 / 缺失 due_at 的脏数据

## 4. 表内使用规则

- 允许做筛选、排序、轻量录入
- 不允许把公式字段当作唯一同步依据
- 不允许将月结统计直接依赖表内临时计算结果
- 关键字段的最终口径以中心主档为准

## 5. 公式字段建议

可以使用，但仅用于展示：
- 剩余天数（展示）
- 是否延期（展示）
- 高风险标签（展示）

真正用于提醒、同步、月结的口径必须由服务端计算并回写实体字段。

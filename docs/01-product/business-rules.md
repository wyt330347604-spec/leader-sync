# 业务规则

> 字段名以 field-dictionary.md 为准，枚举值以 enum-dictionary.md 为准。

## 1. 任务基本规则

1. 一条记录代表一个可追踪、可负责、可完成的任务
2. 每个任务必须有唯一负责人
3. 一个任务可以有多个协作者，但只有一个主负责人
4. 每个任务必须归属于一个月份桶（month_bucket）
5. 每个任务必须有明确的状态
6. 每个任务必须保留发起人、指派人和负责人关系

## 2. 发起与指派规则

### 2.1 发起人
表示"谁提出要做这件事"。

### 2.2 指派人
表示"谁把这件事交给当前负责人"。

### 2.3 负责人
表示"谁对交付结果负责"。

### 2.4 指派关系类型
枚举值（见 enum-dictionary.md）：

- boss_assign：老板指派
- manager_assign：上级指派
- peer_collaboration：平级协同
- self_claim：自领
- carry_over：系统继承

### 2.5 约束
- 负责人不能为空
- 发起人不能为空
- 指派人不能为空
- 系统自动继承的任务，其指派关系类型为 `carry_over`

## 3. 状态规则

允许状态（见 enum-dictionary.md）：

- draft
- assigned
- in_progress
- blocked
- pending_review
- done
- reopened
- cancelled
- closed

规则：

- `done` 代表业务完成
- `closed` 代表归档完成
- `blocked` 必须填写阻塞原因
- `reopened` 必须记录重新打开原因
- `cancelled` 必须记录取消原因

## 4. 进展规则

- 进度百分比范围：0 ~ 100
- 状态为 `done` 时，进度必须为 100
- 状态为 `draft` 时，进度默认为 0
- 任何进展更新都应写入进展日志

## 5. 日期规则

- `start_at` 可为空
- `due_at` 必填
- `completed_at` 在任务完成时自动写入，也允许人工修正
- `days_to_due` 由系统计算
- `is_overdue` 由系统计算

## 6. 延期规则

任务满足以下条件时判定为延期：

- 当前时间 > `due_at`
- 状态不在 `done` / `closed` / `cancelled`

延期后：

- `is_overdue = true`
- 必须允许补充延期原因
- 应进入提醒队列
- 月结时可能转入继承规则

## 7. 老板关注规则

- 老板可标记某任务为重点关注
- PMO 可受托代操作
- 老板关注任务在员工、leader、老板视图均需显著展示
- `boss_attention_flag` 属于管理标记字段，仅限老板/PMO 编辑

## 8. 协作者规则

- 协作者不改变主负责人
- 协作者可收到提醒
- 协作者可更新协同说明，但不能代替主负责人完成最终交付，除非权限允许
- 一期协作者仅在中心主档和网页应用中管理，不做外部双向同步

## 9. 任务完成规则

任务可完成的前提：

- 状态已到 `pending_review` 或 `in_progress`
- 没有未解除的阻塞
- 有完整的最新进展记录

完成后：

- `status = done`
- `completed_at` 写入
- 同步到外部系统
- 进入月结统计候选

## 10. 可见性规则

- 员工默认只看到自己负责、自己发起、自己协同的任务
- leader 默认看到其团队成员的任务
- 老板和 PMO 默认可看全量
- 所有查看范围受角色权限和组织关系共同约束

## 11. 继承规则

任务在月结时满足以下条件则可继承：

- 月底仍未完成
- 未取消
- 未关闭
- 未明确排除继承

继承策略：**新建记录**（不更新原记录）

继承后：

- 新建一条任务记录，`month_bucket` 设为新月份
- `is_carried_over = true`
- `carried_from_task_uid` 指向原任务的 `task_uid`
- `carry_over_count` = 原任务 `carry_over_count` + 1
- 原任务保持不变（状态、月份归属不修改），纳入上月快照
- 在月快照中记录"从上月继承"

## 12. 审计规则

以下操作必须写审计日志：

- 创建任务
- 指派任务
- 修改负责人
- 修改截止日期
- 标记完成
- 延期
- 重新打开
- 月结
- 同步冲突处理

# 错误处理与异常恢复

## 1. 目标

定义系统的错误分类、处理方式、重试策略和人工介入规则。

## 2. 错误分类

### 2.1 业务错误
- 状态流转非法
- 无权限
- 月结锁定后修改统计口径
- 指派关系不合法

### 2.2 同步错误
- 外部 API 调用失败
- 回调验签失败
- 外部映射缺失
- 同步版本冲突

### 2.3 基础设施错误
- 数据库不可用
- Redis 不可用
- DNS/证书异常
- 服务器磁盘不足

## 3. 处理策略

### 3.1 可重试错误
- 网络抖动
- 外部 API 限流
- 临时 token 失效

处理方式：
- 进入 retry queue
- 指数退避
- 记录重试次数

### 3.2 不可重试错误
- 参数错误
- 签名错误
- 数据结构不合法

处理方式：
- 记录失败日志
- 标记 dead-letter
- 等待人工处理

## 4. 同步冲突处理

冲突条件示例：
- 同一字段在短时间内被两个来源更新
- 外部系统版本落后于中心主档
- 月结冻结后仍试图修改统计字段

处理方式：
- 标记 `conflict_flag = true`
- 写入 `sync_conflict` 表
- 通知 PMO/管理员
- 提供“采纳 A / 采纳 B / 手工合并”入口

## 5. 告警策略

### 5.1 立即告警
- 回调连续失败
- 月结失败
- 数据库连接失败
- 证书过期

### 5.2 聚合告警
- 同步失败率高于阈值
- 重试队列堆积
- 某一外部系统 15 分钟内不可用

## 6. 最低日志要求

- trace_id
- task_uid
- source_type
- source_event_id
- operator_user_id
- error_code
- error_message
- stack
- retry_count

# 项目驱动督办系统 · 产品规划蓝图

> 状态：规划已确认（2026-06-03）。从"任务月度督办"升级为"项目驱动的执行与问责系统"。
> 三个关键决策已由项目负责人拍板（见 §6）。**V0 已上线（2026-06-03）**，见 §7（含实际落地）。下一步 V1。

## 1. 定位与价值链
把系统从"离散任务的月度催办"升级为"以项目为中心、时间线驱动、责任到人的执行与问责系统"。

```
项目 → 子项目 → 任务 → 个人(PIC/负责人)
         ↓时间线           ↓
      分层甘特         事故/追责
                          ↓
                  KPI → 晋升（决策支持，人审）
```

**北极星指标**：子项目里程碑按时达成率（on-time milestone rate）。

## 2. 今天的真问题
1. 任务离散、按象限+月份催办，脱离"服务于哪个项目目标"的上下文。
2. 项目是扁平标签（`project.category`，无层级），无法表达 项目→子项目→任务。
3. 时间线只有任务级甘特，无项目/子项目级滚动时间线。
4. 事故、打分、晋升各自为政，无"基于项目执行结果"的统一链路。

## 3. 精益画布（内部工具版）
- **问题**：项目无全貌 / 任务脱离目标 / 时间线只到任务级 / 问责激励无客观依据
- **客户细分**：Boss(决策)、PMO(运营)、Leader/PIC、员工。早期采用者 = Boss+PMO
- **UVP**：项目穿透 + 时间线问责——一屏看清所有项目健康度并追到人
- **解决方案**：三级结构 + 分层甘特 + PIC + 事故联动 + KPI 决策支持
- **渠道**：飞书内嵌 + 卡片提醒 + 月报
- **组织价值/ROI**：决策提速、交付准点率↑、问责透明、激励公平
- **成本**：研发迭代、项目结构录入维护、组织流程变更阻力（最大隐性成本）
- **关键指标**：里程碑准点率、任务项目归属率、未归属积压、驾驶舱使用率、事故闭环率
- **门槛优势**：已沉淀真实组织数据 + 飞书深度集成 + 已有任务/事故/打分基建

## 4. 最小 MVP
**MVP 假设**：打通"项目→子项目→任务"+ 项目级时间线 + 强制归属，领导层就会用它做项目决策，不再回多维表格。

**做**：子项目实体(自关联) / 任务必挂项目+未归属桶 / 驾驶舱项目主视图(三级下钻) / 项目+子项目级甘特。
**不做（后置）**：KPI 自动算分、晋升自动建议、关键路径/资源负载、事故↔KPI 自动联动。

## 5. 路线图 & 版本分级

| 版本 | 主题 | P0 必须 | P1 应有 | P2 可选/谨慎 |
|---|---|---|---|---|
| **V0** 地基 | 数据模型+强制归属 | project 自关联(子项目)；task 默认未归属、可挂项目；未归属 triage 桶 | — | — |
| **V1** 项目驾驶舱 | 可视化穿透+时间线 | 项目组合首屏；三级下钻；项目/子项目级甘特(健康度配色) | 项目 PIC 字段+按 PIC 过滤 | 跨项目资源视图 |
| **V2** 问责闭环（✅已上线 2026-06-04） | 事故×项目 | 事故关联 项目/子项目/任务；项目视图显示关联事故 | 逾期/连续延期→事故建议 | 责任分布热力 |
| **V3** 绩效支持 | KPI 决策支持(人审) | 个人面板聚合"按项目完成+关联事故"作为打分输入 | 季度绩效报告 | 晋升参考视图(纯决策支持) |

顺序刻意为 结构→可视化→问责→绩效。绝不先做 KPI/晋升。

## 6. 已确认的关键决策（2026-06-03）
1. **子项目实体** = `project.parent_project_uid` 自关联，不建独立表。"子项目"= parent 非空的 project；复用项目全部能力。**限两级**（项目→子项目），子项目不可再有子项目（应用层约束）。
2. **强制归属** = 任务创建默认"未归属"(`project_uid = null`)，移除"自动落默认项目"的兜底；提供创建时就地选(子)项目；"未归属"作为醒目 triage 桶。
3. **KPI/晋升** = 只做决策支持，永远人审。系统聚合"项目完成度+事故"作为打分输入，绝不自动定分/自动晋升。

## 7. V0 详细设计（待首肯）

### 7.1 数据模型
- Migration `0011_project_parent.sql`：
  - `ALTER TABLE project ADD COLUMN parent_project_uid varchar(64);`（可空；null=顶级项目，非空=子项目）
  - `CREATE INDEX idx_project_parent ON project(parent_project_uid);`
  - 不加硬 FK（与现有迁移风格一致，约束在应用层）。
- `db/src/schema/project.ts`：加 `parentProjectUid`。
- 应用层约束：① 子项目的 parent 必须是顶级项目（防三级）；② parent ≠ self；③ 删除有子项目的项目需先处理子项目。

### 7.2 行为变更
- `createTask`：移除 `getDefaultProject` 自动兜底 → `projectUid = dto.project_uid ?? null`（不填=未归属）。
- 任务改挂项目：复用 `PATCH /tasks/:uid`（确认/补 `project_uid` 字段支持）。
- 项目设/改 parent：项目模块 create/update 支持 `parent_project_uid`（带两级校验）。

### 7.3 UI（最小）
- Quick-add：加就地"(子)项目"选择器，可留空=未归属。
- 任务列表"按项目"分组：未归属作为醒目分组（已基本支持，加计数/视觉强调 + triage 提示）。
- 项目管理页：支持给项目指定 parent（即建子项目）、按 项目→子项目 两级展示。

### 7.4 测试计划
- createTask：不填 project → `project_uid=null`（未归属，非默认项目）；填了 → 该项目。
- project：设 parent 成功；parent 为子项目时拒绝（两级约束）；parent=self 拒绝。
- 列表：未归属任务进未归属分组。
- 回归：现有按项目分组、私有可见性、from 过滤不受影响。

### 7.5 验证（上线后）
- 看板：任务项目归属率、未归属积压数（趋势）。4 周目标归属率 >70%。

### 7.6 风险
- 存量任务当前都挂在默认项目"公司建设"——V0 不动存量（只改新建行为）；存量是否要批量"打散重新归属"另行决定。
- 未归属桶若长期积压 = 强制点/选择器体验有问题，需迭代。

## 8. V1 详细设计 · 项目驾驶舱（V1 全部已上线 2026-06-04：a 数据+b 首屏+c 分层甘特+d PIC）

目标：让驾驶舱"首先看到有哪些项目"。项目组合首屏 → 三级下钻（项目→子项目→任务）→ 分层时间线，健康度驱动。

### 8.1 信息架构 / 视图归属
- 驾驶舱新增「**项目**」主 tab，**置于首位**；对 boss/pmo/admin 默认进此 tab。
- 权限：boss/pmo/admin 看全公司项目组合；leader 看自己 PIC/负责范围的项目；员工不进项目 tab（维持 me 视图）。与现有 company-view 门禁一致。

### 8.2 数据 / API
- **GET /api/v1/dashboard/projects**（company-view 门禁；leader 限自己范围）返回项目组合树：
  ```
  [{ projectUid, name, category, region, ownerName, picUserId, picName,
     health: 'on_track'|'at_risk'|'overdue',
     progress: 0-100,                       // 滚动完成率
     counts: { total, done, overdue },
     spanStart, spanEnd,                     // 时间线区间
     subProjects: [ { …同结构，无 subProjects } ] }]   // 限两级
  ```
- **滚动口径**（rollup）：项目级聚合 = 其直接任务 + 所有子项目的任务（传递）。子项目级 = 其直接任务。
  - progress：cumulative 完成率（done / 适用任务，复用 shared-types/metrics 口径）。
  - spanStart = min(task.start_at ?? created_at)；spanEnd = max(task.due_at)。
- **健康度规则**（默认，可调）：
  - `overdue`：存在已过期未完成任务（due_at < 今天 且 status ∉ 终态）。
  - `at_risk`：无逾期，但"已耗时间比例 − 完成比例 > 20%"，或距 spanEnd ≤ 7 天且 progress < 80%。
  - `on_track`：其余。
- **PIC（P1）**：migration `0012` 给 project 加 `pic_user_id varchar(128)`（真实用户，可过滤/追责）；`ownerName` 保留为展示自由文本。

### 8.3 前端
- 驾驶舱「项目」tab（首位，gated）。
- **项目组合首屏**：项目卡片网格——左色条(分类/健康度) + 名称 + 进度环 + PIC/负责人 + 子项目数 + 任务数(总/逾期) + 健康度标记。按健康度/分类排序。
- **三级下钻**：点项目就地展开子项目 → 点子项目展开任务（复用任务行）。
- **分层甘特**：项目 bar（span+健康度配色）→ 展开子项目 bar → 任务 bar。扩展现有 GanttChart 支持层级行 + 展开折叠。
- **PIC（P1）**：project-modal 加 PIC 选择器（用户搜索，复用 quick-add 的 user search）；项目 tab 顶部按 PIC 过滤。

### 8.4 子阶段（每段：建→测→截图→部署）
- **V1a**：`/dashboard/projects` API + 健康度/rollup 纯函数 + 单测（健康度三态、rollup、两级聚合）。后端为主，可独立验证。
- **V1b**：项目组合首屏卡片 + 「项目」tab（gated，置首位）。
- **V1c**：三级下钻 + 分层甘特。
- **V1d**：PIC 字段（migration 0012）+ UI + 过滤。

### 8.5 验证（roadmap §5b）
- 「项目」tab 使用率、人均下钻深度（埋点）；月结前提前识别的"预警子项目"数（对比实际延期）；5 人定性访谈"是否用它做项目决策"。
